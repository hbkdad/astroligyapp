# Ephemeris reference fixtures

Status: fixture coordinates and acceptance budget defined; numerical reference
values not yet captured

The versioned fixture manifest is
`tests/fixtures/ephemeris/reference-cases.json`. Its instants and observer
coordinates are inputs chosen to exercise epoch, hemisphere, date-boundary, and
high-latitude behavior. They are not generated by a provider candidate.

## Reference and query policy

Planetary expected values will be captured from the official
[JPL Horizons API](https://ssd-api.jpl.nasa.gov/doc/horizons.html) during the
first candidate adapter spike. Store the complete request URL or parameter set,
raw response, retrieval date, Horizons API version, target identifier, time
scale, center, reference plane, aberration correction, and units beside every
derived expected value. A second reviewer must reproduce the transformation
from the raw response into the normalized contract.

Do not use output from the candidate under test as expected data. Do not update
expected values merely to make a candidate pass. A source or convention change
requires a fixture schema-version change and review.

## Contract conventions

- Instants are strict ISO 8601 UTC strings ending in `Z`.
- Observer longitude is east-positive; latitude is north-positive.
- Domain output uses apparent tropical ecliptic-of-date values normalized to
  `[0, 360)` degrees.
- Each requested body must appear exactly once with provider and data-version
  provenance.
- Angular differences use shortest circular distance, including across zero.

## Acceptance budget

The checked-in tolerances are product acceptance limits, not claims about the
accuracy of JPL Horizons or any candidate. Position longitude and latitude have
a `0.02°` circular/absolute budget. Distance has `0.000001 AU`; longitudinal
speed has `0.001°/day`. These must be tightened if a selected provider's
documented accuracy and reproducible comparisons support it.

JPL Horizons is not an astrology house oracle. The provisional `0.1°` house
budget may only be activated after an independent house algorithm/reference,
its exact house-system conventions, polar behavior, and source version are
recorded. Until then, a provider cannot pass house accuracy acceptance merely
because it satisfies the structural 12-cusp contract.

## Failure policy

Missing source data, unsupported frames, time-scale ambiguity, disagreement
outside tolerance, and polar house failures must remain explicit failures. No
silent fallback, cached substitute, or change of coordinate convention is
permitted.
